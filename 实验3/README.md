## 验收阶段

specification.json按顺序运行：

1. 静态路由下一跳，双向ping并取路由、ARP证据。
2. PC和边缘路由器的路由改成出接口，查远端地址的ARP解析；以实测丢包结果对比下一跳。以太网上能通依赖邻接路由器默认proxy ARP；这不是所有链路的通用结论。
3. 恢复PC下一跳，四台路由器启动RIPv2，查R路由和默认水平分割。
4. 水平分割启用时关闭R1—R2两端接口，查R1改走R3，互ping；恢复。
5. 所有路由链路禁用水平分割，再次关闭、恢复该链路，记录报文差别。
6. 删除RIP，启动OSPF area 0广播网络，查FULL邻居及BROADCAST。
7. 改成OSPF point-to-point，查网络类型和邻居。
8. 关闭R1—R2接口，查备选下一跳205.161.13.2，再恢复邻居和互ping。

OSPF使用实际反掩码0.0.255.255，避免照抄PPT错误的255.0.0.0。三处抓包点分别覆盖PC1局域网、R1—R2、R1—R3，捕获ARP、ICMP、RIP和OSPF流程。需保留各阶段路由表、ARP、OSPF邻居/数据库，以及实际pcap；报告需解释OSPF数据库描述、请求、更新、确认和链路故障过程，不能仅靠ping代替。
