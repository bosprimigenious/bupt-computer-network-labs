\begin{abstract}本实验实现四路由器RIP/OSPF研究拓扑，包含静态路由对照、水平分割、链路故障和协议抓包。当前报告同时保存通过阶段和未通过阶段，完整验收仍待修正debug输出同步并重新运行。\end{abstract}
\section{实验要求与研究问题}
本实验研究RIP和OSPF在自设计四路由器拓扑中的路由计算、更新传播、水平分割、链路故障和恢复过程。报告将静态路由下一跳与出接口写法作为对照，再观察动态协议的debug与抓包。
\section{拓扑与地址规划}
拓扑包含R1、R2、R3、R4和两台PC，R1-R2-R4与R1-R3-R4构成菱形冗余路径。按学号后三位926 mod 255得到161，所有实验地址使用205.161前缀；LAN使用/24，路由器互联使用/30。
\begin{figure}[H]\centering\includegraphics[width=0.96\textwidth]{截图/01-拓扑与配置.png}\caption{四路由器拓扑、地址参数和配置摘要。}\end{figure}\clearpage
\section{静态路由对照}
先在R1/R4上分别使用下一跳和出接口配置静态路由，记录show ip route及端到端ping。这样可以把路由表选择和ARP/出接口行为与RIP/OSPF阶段区分开。
\section{下一跳与出接口的差异}
下一跳写法先解析相邻路由器地址，再由出接口完成二层转发；出接口写法则可能触发以太网ARP或依赖Proxy ARP。报告要同时保存show ip route、show ip arp和ping，不能只凭一条成功回显判断两种写法等价。
\begin{figure}[H]\centering\includegraphics[width=0.96\textwidth]{截图/05-静态路由与ARP.png}\caption{静态路由阶段的ARP检查。}\end{figure}\clearpage
\section{RIP阶段}
默认开启水平分割，观察初始update；关闭R1-R3链路，检查替代路径和路由毒化；恢复链路后检查收敛；关闭水平分割后重复链路故障，比较更新传播。报告中的debug截图来自完整运行记录。
\begin{figure}[H]\centering\includegraphics[width=0.96\textwidth]{截图/02-RIP调试.png}\caption{RIP更新和路由学习输出。}\end{figure}\clearpage
\section{RIP故障切换}
R1-R2链路关闭后，R1应通过R3学习R4 LAN；恢复链路后应回到较优路径。RIP阶段的关键证据是目标前缀的下一跳、metric变化、接口状态和双向ping，而不是单独的debug文字。
\begin{figure}[H]\centering\includegraphics[width=0.96\textwidth]{截图/06-RIP链路故障.png}\caption{RIP链路故障阶段的路由检查。}\end{figure}\clearpage
\section{OSPF阶段}
后续阶段设计为广播网络hello、DBD、LSR、LSU/LSAck和链路故障后的备用路径验证，并保存R1-R2协议抓包和PC1 LAN抓包。OSPF阶段需要先让邻居收敛，再进行ping和show ip ospf database检查。
\begin{figure}[H]\centering\includegraphics[width=0.96\textwidth]{截图/03-OSPF调试.png}\caption{OSPF相关协议输出。}\end{figure}\clearpage
\section{OSPF邻居与数据库}
OSPF广播网络先形成邻居关系，再同步数据库。需要区分FULL邻居、2WAY DROTHER和数据库中的LSA；只看到一条远端路由不能替代邻居、数据库和协议报文的联合证据。
\begin{figure}[H]\centering\includegraphics[width=0.96\textwidth]{截图/07-OSPF邻居阶段.png}\caption{OSPF阶段证据摘要。}\end{figure}\clearpage
