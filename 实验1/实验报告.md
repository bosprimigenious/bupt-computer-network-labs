# 计算机网络技术实践实验一报告

## 一、实验信息

- 实验名称：简单交换机配置与交换网络连通性验证
- 学号：已隐去
- 实验日期：2026年10月13日
- 实验环境：macOS arm64、Dynamips 0.2.25-nojit、Cisco IOS、Python 3.11、TShark 4.6.9

## 二、实验目的

1. 掌握交换机基本启动、接口和二层转发配置。
2. 观察双链路冗余下的生成树协议（STP）转发与阻塞状态。
3. 使用终端互 ping 验证同一二层网络的连通性。
4. 通过未配置地址的负对照，确认验收结果不是由错误拓扑或残留配置造成的。

## 三、实验拓扑与地址

本实验使用两台 c3640 交换机、三台 c2621 模拟PC。SW1与SW2之间配置两条冗余链路；PC1、PC2接入SW1，PC3接入SW2。所有终端位于 `1.1.1.0/8` 网段。

| 设备 | 接口/端口 | 地址 |
|---|---|---|
| PC1 | F0/0 | 1.1.1.1/8 |
| PC2 | F0/0 | 1.1.1.2/8 |
| PC3 | F0/0 | 1.1.1.3/8 |
| SW1 | F1/1、F1/2 | 连接SW2两条冗余链路 |
| SW2 | F1/1、F1/2 | 连接SW1两条冗余链路 |

实验使用自己的 `lab1.net` 拓扑和 `commands/` 配置文件，不直接执行参考仓库脚本。

## 四、实验过程

1. 使用 `_环境/setup.sh` 准备Dynamips、Python依赖和TShark环境。
2. 从空NVRAM启动五台设备，加载自己的拓扑。
3. 为SW1、SW2下发基本交换机配置，为PC1～PC3配置地址。
4. 检查交换机接口状态、端口连接和STP状态，确认一条冗余链路转发、另一条链路阻塞。
5. 依次执行PC1↔PC2、PC1↔PC3、PC2↔PC3双向互 ping，每个方向连续3轮，每轮5个ICMP请求。
6. 使用未配置地址 `1.1.1.254` 做负对照。
7. 保存控制台输出、Dynamips日志和结果JSON，结束后释放本实验启动的进程与端口。

## 五、关键配置

交换机保持默认VLAN 1，启用生成树，不关闭STP。PC配置示例：

```text
ip 1.1.1.1/8
save
```

完整设备命令见本目录 `commands/`，拓扑见 `lab1.net`。

## 七、结果分析

双链路没有造成二层广播环路，说明STP正确选出转发路径并将另一条链路置于阻塞状态。PC1、PC2、PC3均能在同一网段内完成ARP解析和ICMP通信，证明交换机的二层转发路径正常。负对照没有收到响应，说明测试不是由错误地址或残留设备状态造成的。

## 八、实验结论

本次实验完成了交换机基本配置、冗余链路STP验证和三台终端的双向互 ping。按2026年10月13日的历史运行证据，实验一验收通过。公开仓库中的报告版本会隐去学号和本机绝对路径；当前公共运行器后续改动仍应重新回归后再更新“最新通过”结论。
